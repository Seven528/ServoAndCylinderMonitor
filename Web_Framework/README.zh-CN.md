# 网站框架交接包

这份交接包面向修改网页的同事和 Agent。重点是网站的布局、组件组织、状态管理、前后端交互、构建启动和维护规则，而不是 PCB 解析或干涉算法。

## 从这里开始

1. 阅读 [框架与模块地图](docs/ARCHITECTURE.md)，找到要修改的页面区域。
2. 按 [构建与启动备忘录](docs/BUILD_AND_RUN.md) 启动网页外壳或运行测试。
3. 修改交互前阅读 [接口与状态约定](docs/HTTP_AND_STATE.md) 和 [维护约束](docs/MAINTENANCE.md)。
4. 交给其他 Agent 时，直接使用 [接手任务说明](docs/NEXT_AGENT.md)。
5. [交付验证](docs/VALIDATION.md) 记录本次检查结果；`MANIFEST.json` 记录文件校验值和源码来源。

## 什么包含，什么不包含

包含当前网页真实源码，不是重新绘制的示意页面。源码中的 PCB 名称和业务按钮保留，以便直接对照现有网站修改；文档明确指出哪些是通用网站组织方式，哪些需要替换业务适配器。

不包含 C++ 引擎、UNI 数据、真实分析报告、历史聊天、账号凭据、已安装环境、编译产物和旧备份。此包不是完整 PCB 软件发行版，也没有把原网站重构成独立通用框架。

只改布局、样式或通用交互，可从 `web/` 入手。网页外壳可以独立启动，但没有额外安装的原生引擎、Codex 和语音资源时，相关功能显示不可用；不能把外壳可打开等同于业务分析可运行。

## 交接注意事项

- 当前源于工作区实际文件，含未提交修改；Git HEAD 本身不能复现此快照，以包内源码和清单为准。
- 默认 Agent 仅处理主图当前内容；用户本轮明确指定已导入文件或集合时才扩展范围，不要求重复导入。
- 重启意味着新空白会话，不自动备份或恢复旧上传、结果、对话；不要删除磁盘上的原始文件和已有报告。
- Bosch 素材仅沿用已授权的内部演示用途，不能视为对外发布授权。见 [素材说明](source/integrations/local_web_demo/web/assets/BOSCH_ASSETS.md)。
- 本次仅交接文件，不修改或重启当前运行的网站。
